# MathRAG 完整账号管理设计

**日期：** 2026-08-01
**状态：** 已确认
**目标：** 在现有认证体系上增加管理员与教师使用的账号管理功能，并保证教师只能管理自己创建的学生。

## 1. 范围与角色

系统角色由现有的 `admin/user` 调整为：

- `student`：使用问答与自己的会话记录，无账号管理权限。
- `teacher`：除普通学习功能外，可以创建并完整管理自己创建的学生账号。
- `admin`：管理全部账号，并保留知识库、文档和摄取任务等现有管理权限。

本次不增加公开注册。账号只能由管理员或教师创建，其中教师只能创建学生。

本次不包含学生转移、学生认领、物理删除、教师查看学生会话、教师管理知识库或教师管理摄取任务。

## 2. 数据模型

继续使用现有 `users` 表，不建立独立教师学生关系表或通用 RBAC 表。

新增字段：

- `created_by_user_id UUID NULL`：自关联 `users.id`，记录账号创建者。
- `must_change_password BOOLEAN NOT NULL DEFAULT FALSE`：标记账号当前是否使用临时密码。

`created_by_user_id` 使用 `ON DELETE SET NULL` 并建立索引。系统不提供物理删除接口，`SET NULL` 仅作为数据库完整性保护。

角色检查约束调整为 `student/teacher/admin`，默认角色改为 `student`。状态继续使用 `active/disabled`。

教师创建学生时，`created_by_user_id` 写入教师 ID。管理员创建任意角色时写入管理员 ID；管理员创建的学生仍只允许管理员管理。

创建者字段保存历史归属。教师被禁用或改成其他角色时不修改其学生记录；该账号恢复为启用教师后，可以继续管理原先创建的学生。

## 3. 数据迁移

新增 Alembic migration，并按以下顺序执行：

1. 增加允许为空的 `created_by_user_id` 和非空的 `must_change_password`。
2. 将现有 `role='user'` 数据更新为 `role='student'`。
3. 删除旧角色检查约束，建立包含三种新角色的约束。
4. 将角色列默认值由 `user` 调整为 `student`。
5. 建立创建者自关联外键和查询索引。

现有账号的创建者保持为空，`must_change_password` 为 `false`。现有 `admin` 角色保持不变。

降级迁移必须先将 `student` 映射回 `user`。如果库中存在 `teacher` 账号，降级应明确失败，避免静默破坏角色数据；执行降级前需先由管理员处理这些账号。

## 4. 后端架构

在现有 `app.modules.users` 模块中扩展模型、仓储、服务和 DTO，并新增用户管理路由。权限判断集中在服务层，路由依赖只负责确认操作者身份及是否属于账号管理角色。

### 4.1 用户管理接口

- `GET /api/v1/users`：分页查询账号，支持关键词、角色和状态筛选。
- `POST /api/v1/users`：创建账号并设置临时密码。
- `GET /api/v1/users/{user_id}`：读取账号详情。
- `PATCH /api/v1/users/{user_id}`：修改用户名、邮箱、角色或状态。
- `POST /api/v1/users/{user_id}/reset-password`：设置新的临时密码。

不提供 `DELETE` 接口。用户响应不得包含密码哈希或 Session 摘要。管理员列表返回创建者的最小摘要，便于识别账号来源。

### 4.2 自助修改密码

新增 `POST /api/v1/auth/change-password`：

1. 验证当前密码。
2. 校验新密码长度并更新密码哈希。
3. 将 `must_change_password` 清除为 `false`。
4. 撤销该用户全部旧会话。
5. 前端清除认证状态并返回登录页，用户使用新密码重新登录。

认证用户信息增加 `must_change_password`。新增“密码已就绪”依赖：`/auth/me`、`/auth/logout` 和 `/auth/change-password` 仍可访问，其他业务接口在标记为 `true` 时返回明确错误。这样不能只依靠前端跳转绕过临时密码修改要求。

### 4.3 权限规则

学生：

- 不能访问任何用户管理接口。

教师：

- 只能创建 `student`。
- 列表只返回 `role='student' AND created_by_user_id=当前教师ID` 的记录。
- 只能读取、修改用户名和邮箱、启用、禁用、重置自己创建的学生密码。
- 不能修改角色，不能操作其他教师或管理员创建的学生。
- 对范围外目标统一返回 `404`，避免泄露账号存在性。

管理员：

- 可以查询和管理全部账号。
- 可以创建或修改 `student/teacher/admin` 三种角色。
- 不能降级或禁用自己。
- 不能降级或禁用系统中最后一个启用的管理员。

最后管理员校验与目标更新必须在同一事务内执行，并锁定相关管理员记录，避免并发请求同时通过检查。

### 4.4 会话失效

以下操作成功时撤销目标用户的全部有效会话：

- 禁用账号。
- 修改角色。
- 管理员或教师重置密码。
- 用户自助修改密码。

修改用户名或邮箱不强制撤销会话。恢复启用状态不会自动创建 Session。

## 5. 前端设计

新增路由：

- `/users`：账号列表。
- `/users/new`：创建账号。
- `/users/:id`：账号详情与编辑。
- `/change-password`：强制修改临时密码。

新增 `requiresUserManager` 路由元信息，仅允许 `teacher/admin`。全局路由守卫在 `must_change_password=true` 时强制跳转 `/change-password`；修改完成后清除认证状态并返回登录页。

导航规则：

- 管理员在“管理”区域看到用户管理、知识库、文档管理和摄取任务。
- 教师只看到用户管理。
- 学生不显示管理区域。

账号列表采用表格布局，支持关键词、角色和状态筛选，并显示用户名、邮箱、角色、状态、创建者和创建时间。移动端转换为紧凑的分行布局，避免横向内容溢出。

管理员创建或编辑账号时可以选择三种角色。教师创建账号时角色固定为学生，编辑时不显示角色修改控件。状态使用启用/禁用开关并要求确认；密码重置使用独立确认对话框，不在详情页展示密码。

界面覆盖加载、空列表、字段冲突、无权限、最后管理员保护和网络失败状态。前端路由守卫只用于交互引导，最终权限始终由后端判定。

## 6. 请求数据流

创建账号：

1. 路由完成认证、CSRF 和可信来源检查。
2. 服务层根据操作者角色收敛可创建角色。
3. 服务层规范化用户名和邮箱，检查唯一性并哈希临时密码。
4. 写入创建者、角色、启用状态和临时密码标记。
5. 事务提交后返回不含敏感字段的用户资源。

查询账号：

1. 管理员查询应用前端筛选条件。
2. 教师查询在任何前端筛选条件之外强制附加创建者和学生角色范围。
3. 分页和总数查询使用相同的权限范围。

修改账号：

1. 在事务中读取并锁定目标账号。
2. 服务层验证操作者与目标账号的关系。
3. 对管理员角色和状态变更执行自我保护及最后管理员检查。
4. 更新允许的字段，并在需要时撤销 Session。

## 7. 错误处理

继续使用现有应用错误信封和请求 ID。新增或细化以下错误语义：

- 用户名或邮箱冲突：`409`。
- 输入字段、角色或状态无效：`422`。
- 学生访问管理功能：`403`。
- 教师访问范围外账号：`404`。
- 禁用或降级自己、破坏最后管理员保护：`409`。
- 临时密码尚未修改：`403`。
- 当前密码错误：`422`，不区分更详细的认证失败原因。

所有写接口继续执行现有 CSRF 和可信来源校验。

## 8. 验证策略

后端测试：

- Alembic 升级、降级、旧角色转换、自关联外键、索引和检查约束。
- 用户服务的完整角色权限矩阵及教师数据隔离。
- 创建者记录、唯一性冲突、允许字段和角色转换。
- 禁用、角色修改、密码重置和自助修改密码的 Session 撤销。
- 自我保护及并发条件下的最后管理员保护。
- API 分页筛选、CSRF、可信来源、越权隐藏和错误信封。
- 临时密码用户只能访问允许的认证接口。

前端测试：

- 三种角色的导航可见性和路由守卫。
- 临时密码强制跳转及修改成功后的重新登录流程。
- 用户列表筛选、分页、空状态和失败状态。
- 管理员与教师创建表单的角色选项差异。
- 账号编辑、状态确认和密码重置交互。

端到端测试：

1. 管理员创建教师。
2. 教师首次登录并修改临时密码。
3. 教师创建并管理自己的学生。
4. 另一教师无法发现或操作该学生。
5. 学生无用户管理入口且直接访问被拒绝。
6. 管理员可以管理全部账号，最后管理员保护生效。

同时更新 OpenAPI 前端类型、`scripts/create_user.py` 的角色参数和项目启动说明。

## 9. 完成标准

- 数据迁移可在现有数据库上完成且旧账号可以继续登录。
- 管理员能够完整管理全部角色账号，保护规则不可绕过。
- 教师只能完整管理自己创建的学生账号。
- 学生没有账号管理能力。
- 临时密码强制修改在前后端同时生效。
- 所有会话撤销规则可验证。
- 后端、前端与端到端测试通过，OpenAPI 类型与文档同步。
