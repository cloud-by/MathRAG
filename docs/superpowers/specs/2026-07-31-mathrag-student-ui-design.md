# MathRAG 学生问答前端 UI 设计规格

## 1. 文档信息

- 文档状态：已批准，待 Figma 制作与实现计划
- 编写日期：2026-07-31
- 适用项目：MathRAG M6 Vue 3 前端
- Figma 文件：[MathRAG](https://www.figma.com/design/LQnyfqsof0wggZ1IfK6NbZ/MathRAG)
- 设计范围：学生端登录、历史会话、数学问答、答案、解题步骤与引用
- 首版设备策略：桌面优先，同时完整适配手机

## 2. 背景与目标

MathRAG 已具备基于 FastAPI、PostgreSQL/pgvector 和 OpenAI-Compatible API 的持久化数学问答能力。当前原生 HTML/CSS/JavaScript 前端适合作为功能基线，但尚未接入登录、持久化会话和新版 `/api/v1` 契约，也无法为学生提供清晰的长答案、推导过程和引用浏览体验。

M6 首版 UI 的目标是建立一个克制、可信、易读的数学学习界面，让学生无需理解 RAG 技术细节即可完成以下闭环：

```text
登录 → 新建或恢复会话 → 提交数学问题 → 等待生成
→ 阅读答案与推导 → 按需查看引用 → 继续追问
```

成功标准如下：

- 学生能够快速识别结论、推导步骤和引用证据之间的层级。
- 对话是主任务，引用和检索详情不会抢占默认阅读空间。
- 桌面端与移动端都能完整完成核心流程。
- UI 状态可以直接映射到当前 `/api/v1` 认证、会话、消息和 RAG 响应。
- 公式、长答案和引用内容在常见屏幕宽度下保持可读。

## 3. 范围

### 3.1 首版包含

- 用户名和密码登录。
- 新建会话、恢复历史会话、搜索历史会话。
- 用户消息、助手回答、数学公式和推荐追问。
- 回答结论、分步推导、使用知识与引用来源。
- 引用侧栏、检索详情折叠区和移动端引用面板。
- 生成中、空状态、错误、重试、会话归档和引用缺失状态。
- 桌面端 1440px 高保真设计与移动端 390px 高保真设计。
- 核心可点击原型、组件状态和开发标注。

### 3.2 首版不包含

- 公开注册、找回密码、OAuth 或第三方登录。
- 管理员知识点 CRUD、PDF 上传、文档管理和导入任务界面。
- 面向教师的班级、作业、批改或学习分析功能。
- 语音、手写识别、图片题目上传或 OCR。
- 对检索分数、chunk ID 等内部信息的默认展示。
- 深色模式和多品牌主题。

管理员能力保留在后端契约中，但其界面在学生问答体验稳定后单独设计。

## 4. 方案选择

本次比较了三种布局方向：

1. 对话主导并配合按需展开的引用侧栏。
2. 左侧聊天、右侧答案与引用始终并列的双栏研究工作台。
3. 以独立解题报告为中心、弱化连续对话的结构化页面。

采用方案 1。它最符合学生连续提问的心智模型，同时能在需要时提供可验证的引用依据。方案 2 信息密度偏高，容易重现当前原型中长页面与双栏竞争注意力的问题；方案 3 适合打印和复习，但连续追问体验较弱。

## 5. 信息架构

### 5.1 路由

沿用项目总体架构中已经确定的路由边界：

```text
/login                         登录
/chat                          新建数学问答
/conversations                 会话列表
/conversations/:id             指定会话
```

登录成功默认进入 `/chat`。从历史会话打开内容时进入 `/conversations/:id`。未登录访问受保护页面时跳转到 `/login`，登录完成后返回原目标页面。

### 5.2 桌面布局

桌面应用采用三层结构：

1. 左侧会话栏：品牌、新建对话、会话搜索、历史会话列表和用户菜单。
2. 中央问答区：欢迎态、消息流、结构化答案、推荐追问和输入框。
3. 右侧引用栏：默认收起，按引用标记或工具栏按钮展开。

建议尺寸：

- 设计基准画板宽度为 1440px。
- 左侧会话栏宽度约 256px，可折叠。
- 中央内容区占据剩余空间，正文阅读宽度控制在 720–800px。
- 右侧引用栏宽度约 360–400px，以覆盖层或可收起分栏方式出现。
- 输入区固定在中央问答区底部，消息流独立滚动。

右侧引用栏展开时不得将中央正文压缩到不可读宽度。视口不足时改为覆盖式抽屉。

### 5.3 移动布局

移动端采用单栏结构：

- 会话栏变为从左侧打开的抽屉。
- 引用栏变为底部面板；内容较长时可提升为全屏详情。
- 输入区固定在底部安全区域上方。
- 顶部栏保留会话入口、当前标题和引用入口。
- 公式块允许自身横向滚动，页面本身不得横向溢出。

移动设计以 390px 宽度为主要基准，同时验证 320px 宽度下的降级表现。

## 6. 页面与状态

### 6.1 登录页

登录页使用居中单卡布局，包含品牌、简短价值说明、用户名、密码、登录按钮和错误提示。首版没有注册入口或找回密码入口，避免展示不可用操作。

状态包括：默认、输入聚焦、提交中、凭据错误、会话失效和服务不可用。

### 6.2 新对话欢迎态

欢迎态不使用长篇系统消息。中央区域包含：

- 简短问候与能力说明。
- 3–4 个覆盖不同数学类型的示例问题。
- 始终可见的主输入框。
- 对引用、公式和历史保存能力的低强调度说明。

### 6.3 问答态

用户消息保持简洁，助手消息采用结构化回答而不是普通聊天气泡。每次助手回答依次展示：

1. 结论摘要。
2. 核心公式或结果。
3. 分步推导。
4. 使用到的知识点。
5. 行内引用标记。
6. 推荐追问。

对话内容自然向下增长，但消息流独立滚动。输入框始终容易返回，并支持 Enter 发送、Shift+Enter 换行。

### 6.4 生成中

生成过程按后端实际阶段提供渐进反馈：

```text
正在理解问题 → 正在检索知识 → 正在组织解答 → 回答完成
```

如果当前 API 只能提供单一等待状态，首版以顺序动效表达进度，不伪造精确百分比。提交期间禁止重复发送同一请求；网络重试复用原 `client_request_id`。

### 6.5 历史会话

会话列表按最近更新时间排序，展示标题和相对时间。当前会话有明确选中状态。搜索仅过滤当前用户可见会话。

空历史显示简短说明和“开始第一次提问”操作。已归档会话允许阅读，但输入区禁用，并提供新建会话入口。

### 6.6 引用侧栏

引用侧栏包含两个信息层级：

- 默认层：引用编号、来源标题、相关摘要、难度、关键词和被引用位置。
- 高级层：检索子问题、匹配分数、chunk ID、source ID 等调试或研究信息。

高级层默认折叠。点击回答中的 `[1]`、`[2]` 等标记时打开侧栏并聚焦对应引用；关闭侧栏后焦点返回触发标记。

## 7. 视觉系统

### 7.1 设计原则

- 现代学术工具：克制、可信、留白充足。
- 内容优先：装饰不得影响公式、步骤和引用阅读。
- 蓝紫色只强化关键动作、选中状态和引用关系。
- 通过排版、间距和边界建立层级，不依赖大量阴影或渐变。

### 7.2 色彩方向

首轮视觉稿使用以下方向，最终值在 Figma Variables 中统一调整：

- 页面背景：冷灰白。
- 内容表面：白色。
- 主文字：深蓝灰。
- 次要文字：中性灰。
- 主色：低饱和蓝紫色。
- 成功：青绿色。
- 处理中：琥珀色。
- 错误：克制的红色。

文本和交互控件应达到 WCAG AA 对比度。不能只用颜色表达错误、选中或完成状态。

### 7.3 字体与公式

- 中文正文优先使用思源黑体或可靠的系统中文无衬线字体。
- 拉丁字符和数字优先使用 Inter。
- 数学公式沿用 KaTeX 字体与渲染规则。
- 正文基准字号为 16px，正文行高约 1.7。
- 标题不追求夸张尺寸，重点依靠字重和间距区分。
- 块级公式拥有独立留白和横向滚动容器。

### 7.4 间距与形状

- 使用 8px 间距网格。
- 主要卡片圆角为 12–16px。
- 按钮、输入框和可点击列表项的状态边界清晰。
- 阴影只用于浮层、抽屉和固定输入区，不用于堆叠普通内容。
- 移动端触控目标最小为 44×44px。

## 8. 组件架构

Figma 组件应与后续 Vue 组件边界保持一致，但不绑定具体内部实现。

### 8.1 基础组件

- Button：primary、secondary、ghost、danger；default、hover、pressed、focus、disabled、loading。
- TextField、PasswordField、SearchField、ChatComposer。
- IconButton、Tooltip、Badge、Tag、InlineAlert、Skeleton、ProgressStatus。
- Drawer、BottomSheet、Dialog、DropdownMenu。

### 8.2 业务组件

- AppSidebar、ConversationListItem、UserMenu。
- UserMessage、AssistantAnswer、AnswerSummary、SolutionSteps。
- MathBlock、KnowledgeTags、SuggestedQuestions。
- CitationMarker、CitationCard、CitationPanel、RetrievalDetails。
- EmptyConversation、ArchivedConversationNotice、RequestErrorCard。

每个业务组件都需要定义默认、加载、空、错误、禁用和长内容状态中实际适用的部分。

## 9. 数据与交互映射

### 9.1 认证

登录使用服务端 Session Cookie。前端不保存原始会话令牌。登录后通过 `/api/v1/auth/me` 获取当前用户；401 统一回到登录页。

### 9.2 会话

会话列表和详情由 `/api/v1/conversations` 系列接口提供。界面只显示当前用户的会话。创建新会话后再发送首个问题。

### 9.3 问答

发送问题时提交 `conversation_id`、`client_request_id`、`question` 和 `top_k`。历史消息由服务端读取，前端不重复提交历史副本。

回答 UI 对应以下公开数据：

- `answer`：结论和主体说明。
- `steps`：分步推导。
- `used_knowledge`：知识标签。
- `related_questions`：推荐追问。
- `references`：引用侧栏内容。
- `agentic_plan`：检索详情。
- `reasoning_content`：不默认展示；只有产品明确需要且内容适合面向用户时再增加入口。

## 10. 错误与边界处理

- 网络中断：保留用户输入和已插入的问题消息，提供原请求重试。
- `RAG_REQUEST_IN_PROGRESS`：显示请求仍在处理，不创建第二次请求。
- 会话归档：保留只读历史，禁用发送并引导新建会话。
- 登录失效：保存未发送草稿，完成登录后返回原会话。
- 引用缺失：答案保持可读，并说明本次没有可展示的参考知识。
- 公式错误：降级显示原始文本，不让整条消息渲染失败。
- 公式过宽：仅公式容器横向滚动。
- 长引用：摘要优先，完整内容在侧栏内展开。
- 服务端错误：展示稳定错误说明和 `request_id`，不展示堆栈或供应商原始错误。

## 11. 响应式与无障碍

- 桌面基准：1440px；移动基准：390px；额外验证 320px 和常见平板宽度。
- 断点由内容是否仍可读决定，不仅按设备名称划分。
- 完整支持键盘发送、会话导航、打开/关闭引用栏和焦点返回。
- 所有图标按钮拥有可读标签。
- 焦点状态清晰可见，不以 hover 作为唯一反馈。
- 动效尊重 `prefers-reduced-motion`。
- 状态文案可被辅助技术感知，生成中更新避免过度播报。

## 12. Figma 文件组织

当前 Figma 文件只有空白的 `Research` 页面。正式制作时按以下页面组织：

```text
00 Research
01 Foundations
02 Components
03 Desktop
04 Mobile
05 Prototype
```

- `00 Research`：目标用户、核心流程、旧前端基线、方案比较和设计原则。
- `01 Foundations`：颜色变量、文字样式、间距、圆角、阴影和布局规则。
- `02 Components`：基础组件、业务组件、变体和状态。
- `03 Desktop`：1440px 核心高保真画板。
- `04 Mobile`：390px 核心高保真画板。
- `05 Prototype`：桌面和移动核心可点击流程、说明与开发标注。

## 13. Figma 交付阶段

### 阶段 1：基础系统

- 建立颜色、字体、间距、圆角和阴影变量。
- 确定桌面与移动栅格。
- 创建基础交互组件及其状态。

### 阶段 2：核心桌面流程

- 登录。
- 新对话欢迎态。
- 生成中。
- 回答完成。
- 引用侧栏关闭与展开。
- 历史会话恢复。
- 失败与重试。

### 阶段 3：移动适配

- 移动登录。
- 单栏问答。
- 会话抽屉。
- 固定输入区。
- 引用底部面板与全屏详情。

### 阶段 4：交互原型

串联以下主流程：

```text
登录 → 新建对话 → 提问 → 生成 → 查看引用 → 推荐追问
```

同时提供登录失败、请求失败和会话归档三个异常分支。

### 阶段 5：开发交付

- 标注组件名称、状态、间距和响应式行为。
- 将 Figma 业务组件映射到 Vue 组件边界。
- 标明公式、长文本、引用抽屉和焦点管理规则。
- 对照实现截图完成桌面和移动视觉验收。

## 14. 首轮画板清单

首轮预计完成 12–16 个关键高保真画板：

- 桌面：登录、新对话、生成中、回答完成、引用展开、历史恢复、请求失败、归档会话。
- 移动：登录、新对话、回答完成、会话抽屉、引用面板、请求失败。
- 必要时增加组件压力测试画板，验证超长公式、超长标题和多引用内容。

## 15. 设计验证

### 15.1 可用性检查

- 用户首次进入后能否在 10 秒内找到提问入口。
- 用户能否区分最终结论、推导步骤和引用来源。
- 用户能否从引用返回对应答案位置。
- 用户能否恢复历史会话并继续追问。
- 失败后是否清楚下一步操作，且不会意外重复请求。

### 15.2 视觉检查

- 1440px、390px 和 320px 下无页面级横向溢出。
- 长公式不会截断，长答案不会破坏布局。
- 引用侧栏打开后中央正文仍具备合理阅读宽度。
- 颜色对比度、焦点状态和触控区域满足既定要求。

### 15.3 实现检查

- Figma 状态覆盖 `/api/v1` 的成功、401、409、422 和 5xx 场景。
- Vue 组件不直接依赖 Figma 中仅用于排版的容器层级。
- KaTeX 行内公式、块级公式和错误降级均有测试样例。
- 组件测试覆盖发送、防重复提交、重试、引用打开和移动抽屉。
- 浏览器端到端流程覆盖登录、提问、查看引用和恢复历史。

## 16. 最终验收标准

- Figma 文件具备 Foundations、Components、Desktop、Mobile 和 Prototype 页面。
- 颜色、文字、间距、圆角和阴影均通过统一变量或样式管理。
- 桌面和移动核心流程均可点击演示。
- 结论、推导和引用具有稳定一致的视觉层级。
- 所有关键组件包含必要的交互和异常状态。
- 设计能够映射到现有 API 字段，不依赖尚未实现的后端功能。
- 管理端、OCR、注册和其他非首版能力没有混入学生问答范围。
